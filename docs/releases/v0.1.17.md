# TransitHub v0.1.17

本版集中发布仪表盘完整日统计、HTTP 上游兼容及 New API 分组对接三项修复。

## 统计正确性

- 北京时间 00:05 重新读取昨日指定日期用量，不再把最后一次日内页面采样当作完整昨日。
- 营收和成本分别记录完整性，来源失败不覆盖已有有效值；跨日迟到写入与并发日结由唯一数据库入口保护。
- 上游日消费使用明确北京时间，持久站点集合核对缓存，冻结配置至日结提交，部分来源或配置变化不会被标为完整。
- 前端精确匹配昨日，缺失/未核实数据保持未知；周期总额、利润率和续航不使用不完整值生成确定结论。
- 提供同源码维护命令 `reconcile-dashboard`：默认只读预览，明确 apply 和计划哈希后在单事务内回填已经核验来源的历史营收。命令不估算成本，也不把当前倍率追溯套用于旧日。

## 上游与对接

- 恢复统一公网 HTTP/HTTPS 站点兼容，继续保留私网目标拦截、DNS 重验、重定向及敏感头保护；其它 HTTPS-only 业务不随之放宽。
- 修复 New API 混合厂商分组的创建协议选择与错误提示，保留显式选择、原有 Sub2API 主路径及失败边界。

## 升级与恢复

本版在现有日统计表增加完整性字段，既有历史值保留但不自动视为完整日账。历史营收需核对完整来源后使用维护入口补齐；历史成本缺证据时继续未知，不以现配置推算。

先备份并在隔离副本预演，再仅切换应用。历史成本/余额不随营收回填覆盖，派生净利润在成本不完整时仍不作为已确认利润展示。

本 Release 提供 Linux amd64 镜像归档与 `SHA256SUMS`。校验后 `docker load` 导入 `transit-hub:v0.1.17`；镜像 OCI source/revision/version 标识用于核对正式来源。应用回滚仅切回保存的旧镜像，不自动覆盖数据库、Redis 或附件。
