# TransitHub v0.1.19

本版修复历史成本被记成 0、净利润等于营收的问题，并集中修复同一轮排查发现的其它问题。

## 成本与仪表盘

- 每晚成本日结不再因单个上游站点失败而整体放弃：成功站点取指定日实际消费，失败站点用该日最后一次同步的消费兜底；未完成时每小时重试，最近 7 天内没有成本记录的日子自动补跑。
- 后台每 10 分钟及 23:58 记录当日成本，不再依赖有人打开仪表盘；采样前补同步超过 30 分钟未同步的计费站点。
- 成本只会被更可靠的数据覆盖，不会被 0 冲掉；新增 `purchase_recorded` 标志区分“成本为 0”和“没有记录”。
- New API 上游今日消费改按北京时间日界；今日统计失败视为同步失败并保留上次值；令牌续期后立即保存、按站点串行，401 时强制续期重试一次；定时同步出错后仍继续排期。
- 前端：没有成本记录的日子显示为缺口，周期总额注明缺失天数；营收或成本未知时净利润同为未知；预计续航按最近 7 个完整日计算；“较前一日”改为“较昨日全天”；营收为 0 时利润率显示“暂无”；切换工作区不再串数据；负数显示为 `-¥`。

## 对接与分组

- New API 上游分组对接改为直接列出我的分组，协议跟随所选分组，厂商匹配的分组标“推荐”；后端在创建远端资源前核对分组平台与账号协议。
- 修复真实对接并发重复、超时重试冲突、“完全解除”中途失败无法续做、New API 倍率表并发改写丢失更新，以及删除工作区后残留对接记录。

## 通知、活动与探活

- 余额预警、倍率变动、自动调价和活动调价通知按所属工作区发送，不再受当前选中的工作区影响。
- 活动结束失败按退避最多重试 5 次，不再每分钟重复通知；原倍率未知时不恢复成 0；开始和结束不受浏览器断开影响；通知时间使用北京时间。
- 旧版手动探活不再使用空 Key，避免被误判为鉴权失败。

## 升级

启动时自动为 `dashboard_daily_stats` 增加 `purchase_recorded`，为 `group_rate_campaigns` 增加 `end_attempts`、`next_end_retry_at`。已结算或成本非零的旧记录视为“有记录”，未结算的 0 成本视为未记录。

升级后，最近 7 天内没有成本记录的日子会按上游实际消费 × 当前充值倍率自动补跑，与每晚日结同口径；7 天以前的日子保持未记录，不估算。即使未开启定时同步，后台也会同步超过 30 分钟未同步的计费站点。

先备份并在隔离副本预演，再仅切换应用。回滚仅切回保存的旧应用镜像，旧版本会忽略新增列，不恢复旧数据库。

本 Release 提供 Linux amd64 镜像归档及 `SHA256SUMS`。核验正式来源与校验和后导入 `transit-hub:v0.1.19`。
