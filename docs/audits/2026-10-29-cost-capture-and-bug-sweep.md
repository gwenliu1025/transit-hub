# 成本记录丢失根因与全面排查修复（2026-10-29）

## 现象

北京时间 10/28 的成本在图表上为 0，净利润等于营收；“较前一日”、利润率、预计续航随之失真。此前也多次出现历史成本/利润“丢失”。

## 已证实根因（成本链路）

1. **夜间成本日结全有或全无，且从不重试。** `WithDailyPurchaseForAccount` 任一计费站点失败（无会话、令牌过期、请求失败）就整体放弃；看板首页“上游余额待处理”的异常站点足以让每晚日结失败。日结只在 00:05 跑一次。
2. **日结失败时只剩“有人打开看板”时的日内采样。** 当天没打开过看板时，营收日结新建的行成本默认 0，`net_profit = 营收`，v0.1.18 起前端照原样展示为 ¥0 成本。
3. **New API 上游“今日消费”按服务器时区取日界**（生产容器为 UTC）：北京时间 08:00 才换日，凌晨会把前一天约 16 小时的消费算进今天，08:00 后今日消费归零。
4. **New API 今日统计请求失败被当成同步成功**，今日消费被置空，看板静默排除该站点。
5. **后台定时同步默认关闭，日结也不续期会话**：零点后 Sub2API 令牌过期即 401，日结失败。
6. 令牌续期结果在后续指标请求失败时被丢弃、或被并发请求用旧会话覆盖；定时同步遇到一次 Redis 读取失败后整条刷新链永久中断。
7. 日结用会话令牌参与“配置变化”比较，定时同步续期令牌即可让日结以“配置变化”失败。

## 修复

- 后端日结（`dashboard/metrics_service.go`）：启动时与每小时 xx:05 检查最近 7 天；昨日营收/成本未完成即重试，更早几天仅补“完全没有成本记录”的成本（与每晚日结同口径，按当前充值倍率）。成本部分成功照常落账并标记未完成，等下一小时重试。
- 后台成本采样：每 10 分钟及 23:58 为每个工作区写入当日成本（只改成本，不改营收和余额），不再依赖有人打开看板；采样前补同步超过 30 分钟（23:40 后 5 分钟）未同步的计费站点。
- 写入合并（`metrics_repository.go`）：新增 `purchase_recorded` 列（首次建列时仅“已结算或成本非零”算有记录，未结算的 0 成本一律视为未记录）。完整日结覆盖并锁定；无真实来源的写入不改成本；日内采样取最新；部分日结只抬高已有记录，不会把成本冲回 0。
- 上游采集（`upstream/`）：单站失败不再拖垮整体，失败站点用该日最后一次同步的缓存消费兜底；New API 今日窗口改北京时间；同步时今日统计失败视为同步失败并保留上次值；令牌续期立即持久化、按站点串行、401 强制续期重试一次；同步无论成败都重新排期；`LastSyncedAt` 取拉取开始时刻；日结比较不再包含会话令牌。
- 实时接口返回 `date`（北京业务日）与 `balanceRecorded`；趋势点返回 `purchaseRecorded`。
- 前端（`dashboardMetrics.ts`、`DashboardView.vue`）：成本未记录的日子显示为缺口而非 ¥0；营收或成本未知时净利同为未知；周期总额只合计有数据的日子并提示缺失天数；预计续航改用最近 7 个完整日的日均成本（不含今天的部分值）；营收为 0 时利润率显示“暂无”；站点余额读取失败显示未知；切换工作区时丢弃旧请求结果、排队刷新；负数显示为 `-¥`；差额按分取整；以服务器日期为今天；“较前一日”改为“较昨日全天”。

## 边界

- 已经过去且没有任何成本记录的日子：部署后 7 天内的会自动补跑成本；更早的保持“未记录”，不估算。
- 失败站点在某天从未同步成功时，该站点当天消费无法得知，该日成本标记为未完成（偏低），站点恢复后下一小时重试会补齐。
- 对接目标锁、管理端倍率写入锁和活动执行锁都是进程内锁，多实例部署时不跨实例生效。
- New API 删除不存在的令牌时返回 HTTP 200 + `success:false`，“完全解除”重试遇到这种情况仍会报错。
- 活动开启过程中进程崩溃，活动会停在 `running`、分组停在 `pending`，暂无自动接管；活动预览中原倍率未知仍显示为 0。
